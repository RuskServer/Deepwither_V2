# ダンジョン制作ガイド

Deepwither_V2のダンジョンは、Java定義とWorldEditの`.schem`ファイルを組み合わせて構築します。
各インスタンスは専用のvoidワールドへ入口だけを配置し、プレイヤーがドアへ近づくたびに次の部屋を生成します。

## スケマティックの配置先

スケマティックは次の場所へ配置します。

```text
plugins/Deepwither_V2/dungeon/<schematicFolder>/<schematicName>.schem
```

例:

```text
plugins/Deepwither_V2/dungeon/eternal_ice/boss_room.schem
```

テンプレートはサーバー起動時に読み込まれるため、追加・置換後はサーバーを再起動してください。

## マーカーブロック

スケマティック内のマーカーは読み込み時に空気へ置換され、生成先には残りません。

| ブロック | 用途 |
| --- | --- |
| 鉄ブロック | 入口ドア。ボス部屋には最低1個必要 |
| 金ブロック | 出口ドア |
| エメラルドブロック | 通常モブのスポーン地点 |
| ダイヤブロック | 報酬箱の配置地点 |
| ラピスラズリブロック | ダンジョン入口のテレポート地点 |
| レッドストーンブロック | ボスのスポーン地点、撃破後の脱出ポータル地点 |

鉄・金ブロックは、スケマティック範囲外または隣接する空気の方向を開口方向として扱います。
意図しない方向を検出しないよう、ドアマーカー周囲の空気は開口側だけにしてください。

## ボス部屋

`DungeonDefinition`の`bossRoomSchematic`に、拡張子なしのスケマティック名を指定します。
`bossMobId`には`CustomMobManager`へ登録済みのカスタムモブIDを指定します。

```java
super(
        // ...
        "boss_room",
        "ghoul_nest",
        "ghoul",
        "frost_pilgrim",
        0L,
        1,
        3
);
```

ボス部屋は通常の`RoomSlot`や出現重みには追加しません。`maxDepth`の最後の1部屋として自動配置されます。
配置後は残りの分岐が閉じられ、ボスが複数生成されることを防ぎます。

ボス撃破後はダンジョンがクリア状態になり、レッドストーンブロックの位置へ脱出ポータルが出現します。
参加者は個別にポータルへ入り、ダンジョン参加前の位置へ帰還します。最後の参加者が脱出するとインスタンスワールドが削除されます。

## 確認コマンド

```text
/dungeonadmin templates
/dungeon start <ダンジョンID>
/dungeon info
```

ボス部屋が読み込めない場合やレッドストーンブロックがない場合は、サーバーログにエラーが出力されます。
